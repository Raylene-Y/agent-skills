# 改稿改到崩溃？我把标书流程交给了 AI

写在前面

用 AI 辅助写长文档翻车，最常见两种情况：

- 口径漂移——第 3 章写准确率 90%，第 7 章变成 85%，没人发现，评审发现了。
- 格式散架——60 多张配图，编号、字体、大小各长各的样，导出一次排版一下午。

前者是内容管理问题，后者是工具链问题。这次写完一份几百页的技术标，两个坑都踩穿了，最后把整套工作流沉淀成了一个可复用的 AI Skill。这篇只聊方法论。

一句话总结

改稿改到第 8 版，最大的敌人不是工作量，是**一致性**。AI 写标书的价值不在"帮你写"，在"帮你不散"。

口径先于文字

多轮改稿里，指标值、模块名、章节结构会不停变。文字可以改，口径不能散。

所以我建了一个"撰写逻辑"文件，所有口径只维护在这一处：

- 指标口径表：每个数字的数值、统计口径、出处。
- 命名口径表：标准名 + 已废弃写法——防止旧名字在第 6 版里复活。
- 结构决策记录：每次结构调整记一笔，含被推翻的旧决策，避免三个月后又翻案。

铁律：改口径先改库，再改正文。领导再说"这个模块改名"，改一处，全文扫一遍废弃名，收工。

规则层：把"评审会挑什么刺"写成检查清单

标书的坑是高度模式化的，踩过的都写成可勾选规则：

- 禁止前向引用。"详见后文 X 章"——后文删了你不知道，评审知道。
- 指标数字必须加粗。评审扫读只看加粗，你埋在段落里等于没写。
- 落选方案只写"场景不适配"。写"功能有限"显得你不专业，还可能冒犯在场的人。
- 结论先因后果。"因为它好所以选它"是循环论证，评审一眼看穿。
- 口语词黑名单。"红线""通吃""背书""生死"这类词一律换书面语。

关键是清单不只给人看——敏感词、编号断链、格式问题都做成了脚本，一键扫，不靠人眼。

管线层：Markdown 一键导出标书 Word

写作全程只用 Markdown（对 AI 协作友好），交付时一条命令：

pandoc 转换 → 自动套甲方模板（页眉页脚样式全继承）→ 表格字体编号自动格式化 → 图题表题合并 → 敏感词终扫。

第一次跑通的时候，以前一下午的排版活变成了 30 秒。

配图管线：AI 生图 → 可编辑 PPT

领导要的架构图，AI 生成的好看但没法改字。解法是把 AI 图当设计稿：脚本反推成 PPT 原生元素，色块、箭头、文本框全部可编辑，再导高清图进文档。领导改配色改文案，PPT 里点一下完事，不用重新生成。

一些真实数字

- 60+ 张配图，统一风格统一格式。
- 32 张手写初稿照片，AI 转录提取。
- 28 个子模块，口径一表管到底。
- N 轮修改意见，没有一次口径打架。

也得诚实

这套东西不便宜：建口径库、写检查脚本、调导出管线，前期大概花了一天半。只在"长文档 + 多轮修改 + 多人协作"的场景回本——写一篇三千字散文用不上，别硬套。

总结

写标书四件套：口径库管一致性，规则清单管评审雷区，导出管线管排版，配图管线管图。前两个是方法，后两个是工具，方法可以抄走直接用，工具我已经封装成 Skill 并开源，GitHub 搜 Raylene-Y/agent-skills，第一个 skill 就是它（pi-bid）。

一句话总结：AI 写长文档的胜负手，不是它写得多好，是你把"不变的东西"管得多死。
