# 云澜市城市数据接入与共享平台 · 总体架构撰写逻辑（虚构样例）

> 本样例演示"撰写逻辑/口径库"方法论在虚构项目上的应用：指标口径、命名口径、结构口径一处定义，结构决策留痕可溯。
> 项目、模块、指标、日期均为虚构；空模板见 ../templates/撰写逻辑模板.md。

## 虚构项目设定

云澜市（虚构地名）拟建城市数据接入与共享平台：接入物联网感知终端与委办局业务系统数据，经治理后向城市运行管理中心提供共享服务。我方负责"数据接入与治理分册"，含消息接入、数据治理、共享服务、运维管理 4 个模块。

## 口径决策表

### 指标口径

| 指标 | 口径 | 出处 |
|---|---|---|
| 峰值接入能力 | ≥ **10万条/秒**，中心机房 3 节点集群实测口径 | 需求 2.1 条 |
| 终端并发连接 | ≥ **3万** 路，单边缘节点 | 需求 2.2 条 |
| 端到端投递时延 | < **500毫秒**，P99 口径 | 需求 2.3 条 |
| 数据共享接口响应 | < **200毫秒**，内网环境 P95 口径 | 需求 4.1 条 |

### 命名口径

| 名称 | 统一写法 | 已废弃写法 |
|---|---|---|
| 消息接入模块 | 消息接入模块 | 接入网关模块 |
| 流处理引擎 | Apache Flink（首次出现全称，后文 Flink） | Flink 流引擎 |
| 数据共享接口 | OpenAPI（斜体不用于正文） | 开放接口/共享 API |

### 结构口径

- 层级：分册 → 模块（4 个）→ 子模块（12 个）。
- 章节组织：选型 → 总体架构 → 系统组成与接口 → 方案设计，自顶向下；标书禁前向引用，衔接处只用回指（"如前所述"）。

## 分章节撰写逻辑（示范 1 节，其余同构）

### 1. 总体架构设计——多维描述

**一句话使命**：把平台自身的架构讲透，分层、交互、流程、指标四个维度自洽。

**行文顺序**：
```
分层视图与模块职责（接入层/治理层/服务层/管理层，各一段，句式统一）
  → 模块间交互机制（消息驱动/同步调用/定时批处理，其一其二其三）
  → 核心交互流程（终端数据从接入到共享的完整链路，收口低耦合）
  → 指标对应关系（每个指标有模块承接，数值与指标口径表一致）
```

**要点**：只讲关系与职责，实现细节留给方案设计；指标数值一律从上方指标口径表取，不在本节新造数值。
